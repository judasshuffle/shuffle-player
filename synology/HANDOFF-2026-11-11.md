## Entry points and architecture

- Screen source: http://shuffle.tplinkdns.com:8001/dr-screen
- Screen client entity script: http://shuffle.tplinkdns.com:8001/dr-screen-entity.js
- Unchanged live MP3: http://shuffle.tplinkdns.com:8001/stream.mp3
- Private LAN dashboard: http://192.168.68.81:8094/
- Public visitor tablet script: http://shuffle.tplinkdns.com:8001/dr-dj.js

The screen stays fullscreen. The cinema EventBridge `hello`/`ready` handshake
receives each visitor's volume, 0–100. Media source → analyser → volume gain →
speakers keeps visuals reactive at low or zero sound. Screen and tablet volume
use `darkride/shufflizer/sound` and the local `darkride.shufflizer` channel,
independent of the cinema. The screen has no station controls.

The owner's separate SHUFFLIZER tablet remote provides typed search, Play now,
Add to queue, Shuffle All and Next. Search previews matches; Play now replaces
the shared queue, Add to queue appends without interrupting playback, Shuffle
All replaces with available indexed tracks in random order, and Next advances.
Only the privately paired owner client can authorize station mutations. Synology
checks HMAC signatures over method, exact route, server epoch, timestamp, nonce
and body hash. Missing/invalid keys fail closed; stale, altered and replayed
requests are rejected. LAN access and avatar/display-name claims grant no
mutation permission. Public root redirects to the screen; dashboard assets
and unsigned library-search endpoints are rejected on public port 8001.
